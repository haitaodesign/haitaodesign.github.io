我把这个专栏 vibe coding 成了一个系统：JDWatch

JDWatch 做一件事：把专栏里常被问到的那些公司，官网在招岗位聚合到一处，让你少在多个招聘站之间来回切换。

它不是二手转载，而是直接对接公司官网招聘站。目前对用户可见的已核验公司有 27 家（字节、腾讯、美团、京东、百度、蚂蚁、阿里系、小红书、米哈游、拼多多、快手、网易、B 站、得物、滴滴、智谱、Dify、携程等），每家都单独适配了对应官网的招聘接口或页面，在招岗位大约一万，每天自动跑一遍。

岗位的时效靠一层新鲜度判断兜着：发布时间超过约两个月的，会自动标成下架，默认列表里不再当作「在招」。这套规则现在还比较简单粗暴，后面还会继续优化。

你可以按公司、城市、方向（前端 / 全栈 / 算法）以及社招 / 校招 / 实习三通道筛选；心仪的岗可以收藏；常用的搜索条件可以存成职位订阅，付费用户还能每周收到一封邮件周报——把「每天盯官网」变成「每周收一封」。缺哪家公司，也可以在产品里直接提交收录申请。

如果你是开发者，或者已经习惯让 AI 助手帮你干活，同一份数据还有另外两种用法。Open API（sk_live_*）、CLI（@jdwatch/cli）和 Skills（jdwatch-skills）是三件套：网页能看的岗位，命令行也能查；装上 Skills 之后，可以直接让 Cursor 一类的 Agent 用自然语言搜岗、建订阅、管理已保存职位。本地还有一层简历 × 在招匹配（jdwatch match）：简历放在你自己机器上，精评在本地完成，不经过 JDWatch 的服务器——这是隐私承诺，也是刻意的边界。

JDWatch 不代你投递，不帮你编简历，不把简历上传到服务器。岗位信息在别处也能搜到，免费账号就能看全量已核验岗位；Pro 主要是提高订阅和收藏额度、每周邮件，以及每月提交新公司收录申请的次数。不强制付费，请自行选择。

入口：https://www.jdwatch.work

剩下的——投递、面试、决定去不去——还是靠你自己。

目前这些功能只是一个起点，后面还有不少想做的方向。你用下来觉得缺什么、哪里不好用、希望先收录哪家公司，欢迎直接告诉我——这些反馈会直接决定我接下来先做什么。
